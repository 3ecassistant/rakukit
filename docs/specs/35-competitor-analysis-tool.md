【① 楽天市場 競合商品分析ツール 仕様書】

■① ツール名称

楽天市場 競合商品分析ツール

仮称：
Rakuten Competitor Analyzer

■② 目的

楽天市場の商品検索キーワードを入力するだけで、競合商品の公開情報を一括取得し、

・市場規模
・価格競争
・レビュー競争
・ショップ競争
・送料条件
・ポイント施策
・主要競合商品

を数値化する。

最終的には、

「この市場で自社商品がどの程度競争できるか」

を判断できる状態にする。

楽天市場商品検索APIでは、キーワード・ショップコード・商品コード・ジャンルなどを検索条件として指定でき、価格、レビュー、ショップ、ポイント、送料、商品説明等を取得できる。

■③ 想定利用者

・楽天市場出店者
・EC責任者
・商品企画担当者
・楽天SEO担当者
・広告運用担当者
・マーケティング担当者

■④ 基本利用フロー

ユーザーが検索キーワードを入力

↓

楽天市場商品検索APIを実行

↓

指定件数の商品を取得

↓

商品コード単位でデータ整理

↓

価格・レビュー・ショップ等を集計

↓

競合市場分析結果を表示

↓

必要に応じてCSV / Googleスプレッドシートへ出力

■⑤ 入力項目

【必須】

・検索キーワード

例：
トートバッグ レディース

【任意】

・ジャンルID
・最低価格
・最高価格
・取得商品数
・除外キーワード
・レビューあり商品のみ
・送料無料商品のみ
・販売可能商品のみ
・ポイントアップ商品のみ

楽天APIでは`keyword`、`genreId`、`minPrice`、`maxPrice`、`NGKeyword`、`hasReviewFlag`、`postageFlag`、`availability`、`pointRateFlag`などを指定できる。

■⑥ 取得件数

選択式とする。

・30件
・100件
・300件

初期値：
100件

APIは1リクエスト最大30件、最大100ページまで指定可能。理論上は1検索条件について最大3,000件までページングできる。

ただしMVPではAPI負荷・分析速度・ユーザー体験を考慮し300件を上限とする。

■⑦ API検索条件

基本検索：

keyword
＋
availability=1
＋
sort=standard
＋
formatVersion=2

を標準とする。

`standard`は楽天APIが提供する「Rakuten standard sort」。価格順、レビュー件数順、レビュー評価順、更新日時順も利用できる。

注意：

本ツール上では「楽天標準順」と表記する。

「楽天市場検索順位」と断定しない。

→ APIのstandard結果と楽天市場フロント画面の検索表示順位が完全一致することを前提としないため。

・itemCode
・itemName
・catchcopy
・itemPrice
・itemUrl
・reviewCount
・reviewAverage
・postageFlag
・pointRate
・pointRateStartTime
・pointRateEndTime
・availability
・genreId
・shopName
・shopCode
・shopUrl
・startTime
・endTime
・itemCaption

API通信量削減のため、`elements`パラメータを利用し必要項目だけ取得する。

■⑨ 商品一覧画面

各商品について以下を表示する。

・順位
・商品画像
・商品名
・ショップ名
・価格

・レビュー評価

・ポイント倍率
・商品URL

順位は、

「今回取得したAPI結果内順位」

として扱う。

■⑩ 市場基本指標

検索結果から以下を計算する。

【市場商品数】

APIの`count`

→ 検索条件に該当する商品総数

【分析対象商品数】

実際に取得・分析した商品数

例：

検索結果総数：58,320件
分析対象：100件

と分けて表示する。

APIレスポンスには検索結果総数`count`が含まれる。

■⑪ 価格分析

算出項目：

・最低価格
・最高価格
・平均価格
・中央値価格
・第1四分位価格
・第3四分位価格

さらに価格帯別商品構成比を算出する。

価格帯は市場に応じて自動生成。

例：

〜2,999円
3,000〜3,999円
4,000〜4,999円
5,000〜5,999円
6,000円〜

→ 平均価格より中央値価格を主要KPIとして扱う。

理由：

極端に高価格・低価格の商品による影響を抑えるため。

■⑫ レビュー競争分析

算出：

・レビュー件数平均
・レビュー件数中央値
・レビュー件数第1四分位
・レビュー件数第3四分位
・レビュー評価平均
・レビュー評価中央値

さらに、

レビュー0件
レビュー1〜9件
レビュー10〜49件
レビュー50〜99件
レビュー100〜499件
レビュー500〜999件
レビュー1,000件以上

の構成比を算出する。

APIでは`reviewCount`と`reviewAverage`を取得できる。

■⑬ レビュー参入障壁スコア

本ツール独自指標として、

「レビュー参入障壁」

を5段階評価する。

★★★★★ 非常に高い
★★★★☆ 高い
★★★☆☆ 標準
★★☆☆☆ 低い
★☆☆☆☆ 非常に低い

基本判定には、

取得商品のレビュー件数中央値

を使用する。

暫定基準：

0〜19件
→ ★☆☆☆☆

20〜99件
→ ★★☆☆☆

100〜299件
→ ★★★☆☆

300〜999件
→ ★★★★☆

1,000件以上
→ ★★★★★

※運用データを蓄積後、ジャンル別に基準値を最適化する。

■⑭ 送料無料分析

算出：

送料無料率
＝
送料無料商品数 ÷ 分析対象商品数 × 100

重要：

APIの出力`postageFlag`は、

0＝送料込み
1＝送料別

として定義されているため、実装時の真偽判定を逆にしない。

表示例：

送料無料率：87%

→ 「検索上位商品の大部分が送料無料」

と評価する。

■⑮ ポイント競争分析

算出：

・通常ポイント商品率
・2倍以上商品率
・5倍以上商品率
・10倍商品率
・平均商品別ポイント倍率

ただし楽天APIの商品別ポイント情報には制約があり、終了まで24時間以内の商品別ポイント倍率は表示されない仕様となっている。

したがって、

「楽天市場上の全ポイント施策を完全取得」

とは表現しない。

またショップ単位のポイント倍率は対象外で、APIが扱うのは商品別ポイント倍率。

■⑯ ショップ競争分析

shopCodeを使用して、

・ユニークショップ数
・ショップ別商品数
・ショップ別構成比

を計算する。

表示例：

検索上位100商品

A店：8商品
B店：6商品
C店：5商品
その他：81商品

さらに、

上位5ショップ占有率
＝
上位5ショップの商品数 ÷ 分析商品数

を計算。

→ 少数ショップが検索結果を占有している市場かどうかを見る。

■⑰ 主要競合商品ランキング

以下のランキングを自動生成する。

・レビュー件数TOP10
・レビュー評価TOP10
・低価格TOP10
・高価格TOP10
・ポイント倍率TOP10

各商品から楽天市場の商品ページへ遷移可能にする。

■⑱ 市場競争力スコア

本ツール独自指標。

100点満点。

構成：

レビュー競争：30点
価格競争：20点
ショップ集中度：20点
送料無料競争：15点
ポイント競争：15点

スコアが高いほど、

「既存競合が強く参入難易度が高い市場」

とする。

表示：

0〜20
→ 競争弱

21〜40
→ やや弱

41〜60
→ 標準

61〜80
→ 強い

81〜100
→ 非常に強い

■㉔ APIエラー処理

以下に対応。

400
→ 入力条件エラー

404
→ 商品なし

429
→ APIアクセス超過

500
→ 楽天API内部エラー

503
→ メンテナンス・一時利用不可

楽天API公式仕様でもこれらのステータスが定義されている。

429・500・503では一定回数のリトライ処理を行う。

ただし短時間に同一URLへ多数アクセスすると、一時的に応答しなくなる場合がある旨も公式ドキュメントに記載されている。

■㉕ API認証

2026-07-01版では、

applicationId
＋
accessKey

が必要。

accessKeyはHTTP Headerまたはquery parameterで送信可能。

原則として、

API認証情報をブラウザJavaScriptへ直接埋め込まない。

Backend経由でAPI通信する。

■㉖ 利用規約上の重要要件

ここはサービス化する場合に必須確認。

楽天Web Service利用にはアプリ登録が必要で、

・アプリ名
・URL
・アプリ種類
・利用目的
・想定QPS

等を登録する仕組みになっている。App IDとAccess Keyはアプリごとに発行される。

また公式利用規約には、

・楽天が明示的に認めた場合を除く収益化に関する制限
・Web Serviceを楽天と競合するサービスへ使用することへの制限
・取得情報の用途や複製・変更に関する制限
・取得情報を不特定多数と共有可能な場所へ保存することへの制限
・特定者だけがアクセスする環境での利用に関する制限

が記載されている。

したがって、

「有料SaaSとして第三者へ販売する」

場合は、

実装前または正式提供前に楽天側への利用可否確認を必須工程とする。

なお公式英訳自体も、日本語版利用規約が正式な規約であるとしている。

【重要まとめ】

「ある検索市場に存在する競合商品の強さを、価格・レビュー・送料・ポイント・ショップ集中度から定量化すること」
